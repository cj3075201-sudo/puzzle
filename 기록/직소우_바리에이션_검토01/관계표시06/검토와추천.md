# 관계 표시 06 — 새 색 없이 같은 기능을 만들 수 있는가

2026-09-27. 최초 요청: 관계 기능의 범위를 설명하고, 실제 직소우 모형에 적용해 보여주며 색을 추가하지 않는 대안을 비교한다. **2안(A)은 제외, 3안(B)은 보류**다. 후속 사용자가 1안+4안을 좁게 시도하고 대화별 모형 목록을 제한하여 재사용을 확인하는 방향을 승인했으며 [재사용 07](../재사용07/검토와결과.md)에서 이어갔다. 이 문서의 최초 비교와 반박은 근거로 보존한다. 본편·기존 Unity의 코드/에셋/빌드는 변경하지 않았다.

## 현재 판단

사용자 번호를 기준으로 정리한다.

| 번호 | 방식 | 현재 상태 |
|---|---|---|
| 1안 | 별도 관계 표시 없이 기존 연결과 문맥으로 해석 | 현행 기준. 모든 구별을 맥락에 맡기는 것이 적절한지는 재검토 중 |
| 2안 = 이전 A | 새 색 관계 조각 삽입 | **사용자 제외.** 불필요하게 길어지는 해결책이라는 판단. 차순위 후보로 재추천하지 않음 |
| 3안 = 이전 B | 접합부 관계 표식 | **사용자 보류.** 활성 추천에서 내림 |
| 4안 = 이전 C | 연결부 형상으로 관계 구별 | 1안의 문맥을 유지하면서 좁게 시도하는 방향 승인. 상세 형상·전체 문법 채택은 아님. 재사용 07로 진행 |

**1안의 유효한 생략·문맥 읽기를 유지하면서, 게임이 플레이어에게 선택하게 하는 서로 다른 의도를 구별할 수 있도록 4안을 최소 범위로 검토하자는 AI 추천을 사용자가 진행 방향으로 수용했다.** 상세 전역 문법까지 채택한 것은 아니다. 이전 B 우선/A 차순위 추천은 종료한다.

같은 상황에서 ‘내가 주민을 너에게 보낸다’와 ‘주민이 나를 너에게 보낸다’ 중 선택하게 한다면, 현재 동등 입력만으로 두 의도를 구별할 수 있는지 확인해야 한다. 같은 입력을 받고 문맥으로 한쪽만 고르면 반대 의도를 말할 수 없다. 이 경우 관계를 명시하는 것은 소통의 표현 수단을 늘린다. 반대로 누가 보내는지 이미 공유된 상황이라면 기존 짧은 발화도 유효하게 남겨야 한다.

기준은 모든 결과 차이·모든 한국어 조사를 의무적으로 표시하는 것이 아니라, **실제로 선택할 수 있게 설계한 의도들을 관측 가능한 입력으로 구별할 수 있느냐**다. 핵심 정보는 무조건 조립, 지칭·의도는 무조건 문맥이라는 전역 이분법도 채택하지 않는다.

방금 제안한 색의 기능은 관계 명시 한 계열이다. 그 안에서 행위자·받는 상대·목적지·소유 등 서로 다른 관계를 표현할 여지는 있으나, 이번에 구체화한 것은 **대상–행동 사이의 ‘이 행동을 하는 쪽’ α 하나**다. 이 기능을 확인했다고 모든 관계·노랑 연결 범위까지 해결된 것으로 확대하지 않는다. 색은 범주를 식별하는 수단이므로 기능이 하나라는 이유만으로 잘못된 설계는 아니다. 다만 같은 표현력을 다른 수단으로 제공할 수 있다면 식별·조립·학습 비용을 비교해야 한다. 새 색의 존재를 정당화하려고 인과·순서·부정 기능을 한꺼번에 붙이지 않는다.

## 같은 내용의 세 물리 배치

공통 발화는 나·주민이 보내다의 두 동등 입력이며, 너는 출력 쪽 상대다. 설명용으로 두 입력 중 한 명이 다른 한 명을 너에게 보내는 한 사건으로 범위를 고정한다. 위/왼쪽 그 자체는 역할이 아니며 회전 금지를 유지한다.

| 안 | 실제로 추가하는 것 | 피스와 조작의 변화 | 이득과 부담 |
|---|---|---|---|
| A. 새 색 α 조각 | 독립된 관계 피스와 그 글자 | 4→5피스. 노랑을 한 칸 옮기고 사이에 삽입. 위 접합은 세로 α 모형, 왼쪽은 가로 모형 | 기존 글자/모형 발견·끼움 조작을 이용. 조각과 길이가 늘며 가지가 복잡하면 주변 배치도 옮겨야 함 |
| B. 접합부 α 표식 | 연결된 경계에 붙이는 관계 글자 | 4피스+표식. 같은 조립을 유지하고 적용할 접합 선택 | 길이와 색을 유지. 작은 표식의 읽기·선택·탈착과 접합에 글자를 붙이는 새 조작이 필요 |
| C. 두 갈래 접합 | 파랑 입력과 노랑 돌출의 대응 형상 | 4피스. 단어 자리를 고정하고 표시를 다른 쪽으로 옮기면 파랑과 양쪽 노랑의 외곽을 바꿈 | 외곽 맞추기와 역할이 연결됨. 모형 종류·학습 부담이 늘고 외곽에 문법 의미를 추가하는 설계 변경 |

**C의 외곽 3개 교체는 항상 필요한 최소 조작이 아니다.** 기존 외곽에 들어간 나/주민 글자를 맞바꾸면 같은 형태로 반대 역할을 말할 수 있다. A/B에도 이 풀이를 허용한다. 글자–모형 분리와 동등 표현을 보존하고, 원하는 단어만 특정 홈에 맞도록 만들지 않는다. 두 갈래는 두 대상을 잇는 입력이 아니라 하나의 접합 형상이며, 그 역할 의미를 노랑–노랑의 모든 연결로 확장하지 않는다.

실제 화면의 C 버튼은 여러 외곽을 바꾼 결과를 한 번에 보여주는 **비교 제어**다. 실제 게임에서도 한 번 클릭으로 세 모형이 자동 교체된다는 규칙을 채택하거나, 이를 한 번의 게임 조작 비용으로 측정한 것이 아니다. A/B 역시 자유 배치·드래그·스냅을 구현한 본편 플레이가 아니다.

## 최소 조립 문제와 판정

1. 보유 정보: 나/주민/너/보내다와 α의 뜻을 이미 배운 조건. 비교에 집중하도록 한국어 뜻과 조립 목표를 제시한다. 미지 언어 학습 문제로 부르지 않는다.
2. 목표: ‘주민이 나를 너에게 보낸다’를 표현한다. 반대 목표로 전환할 수 있다.
3. 선택: 관계를 생략하거나 위/왼쪽 접합에 표시하고, 두 노랑 글자를 교환할 수 있다. 외곽은 회전하지 않는다.
4. 표시된 입력에 주민 글자가 있으면 주민이 보내는 쪽이다. 다른 위치에 같은 뜻을 구성해도 받아들인다. 명시한 역할이 목표와 반대면 ‘다른 관계를 표현했다’고 보여주며 다시 수정한다.
5. 무표지+단서 없음은 두 해석이 남는다고 설명한다. 무표지를 자동 오답, 반대 역할, 정답 추측 성공으로 판정하지 않는다.
6. 주민/나의 출발 준비 단서를 켜면 문맥상 유력한 해석을 비교한다. 준비 자세만으로 반대 제안을 논리적으로 배제하지 않는다. 명시한 역할은 단서와 충돌해도 유지한다.
7. 표지가 정하지 않는 것: 보고/요청, 계획 수락, 실행 가능성, 사실 여부, 다른 긴 명사 연결의 설명 범위.

한국어 전체 풀이 버튼은 이번 **설계 비교용 해설**이다. 본편 전체 문장 자동 번역 기능이 아니다. 작은 문제에서 역할 표지가 필요하도록 정보를 제한했다고, 실제 모든 대화에 표지를 강제해도 된다는 뜻은 아니다. 무표지 발화가 자연스럽게 통하는 문맥은 본편에 남아야 한다.

## 반론과 처리

- ‘B도 새 기능 아닌가?’ 맞다. 색을 추가하지 않지만 접합 표식이라는 새 입력을 더한다. 공짜 개선이라고 설명하지 않는다.
- ‘표식을 옮기기만 하면 퍼즐이 너무 쉽지 않나?’ 이 예시는 관계를 담는 방법의 비교다. 판에 들어가는 조각 수나 표식 이동만으로 본편 깊이가 생긴다고 주장하지 않는다. 더 어려운 정답을 만들려고 우연 진행·짧은 동등 표현을 차단하지 않는다.
- ‘색 하나가 별도 범주를 알려주는 장점도 있지 않나?’ 최초 비교에서는 A의 장점으로 평가했으나, 후속 사용자가 길이 증가를 이유로 2안(A)을 제외했다. 이 장점을 근거로 제외안을 자동 복원하지 않는다.
- ‘형상을 쓰면 직소우답지 않나?’ C는 비교 가치가 있지만, 같은 관계 기능을 위해 모형 목록과 문법을 함께 늘리는 비용이 있다. 먼저 단어/외곽 분리와 무표지 모형을 유지하는 범위에서 비교해야 한다.
- ‘집 안의 열쇠와 집 안에서 찾기를 해결했나?’ 아니다. 이 α는 행위자만 명시한다. 수식 범위·위치와 행동 장소의 구별은 여전히 별도 설계다.

## 에이전트 검토와 확인 범위

- `relation_alternatives06`: 대화 이력 없이 현재 제약과 요청을 받아 대안·비용을 독립 검토. B를 우선 비교하되 새 부착 조작임을 드러낼 것, C에서 글자 교환도 가능하므로 외곽 3개 교체를 필수 비용으로 계산하지 말 것을 지적했다. 도면과 비교 조작에 반영했다.
- `jigsaw_geometry`: 삽입 한 칸, 가로/세로 α 모형, 접합 단위의 범위, 무표지 유지, 두 갈래를 한 접합으로 표현할 조건을 검토했다. 이후 수정된 PNG 두 장을 직접 보고 생성 코드·HTML과 대조했다. 기하 9배치와 의미 함수 108조합을 읽기 전용으로 재검사했고, 동등한 글자 교환·명시/무표지 구별·문맥 충돌 보존을 확인했다. 브라우저 플레이를 수행했다는 주장은 하지 않았다. 추가 중대 수정사항 없음.
- [접합 검사](접합검사.json): 3방식×무표지/왼쪽/위쪽 9배치의 돌출·홈 대응, 본체 겹침 없음, 여백 검사를 통과했다. 모든 홈을 닫는 표본이라는 사실을 전체 게임의 필수 완성 조건으로 확대하지 않는다.
- [비교 화면 동작 검사](화면동작검사.json): 3방식 각각 무표지 해석·반대 역할·글자 교환에 의한 동등 표현·생략 복귀·문맥 충돌·초기화·노랑 클릭 교환을 확인했다. 브라우저 오류 없음, 820px 폭의 가로 넘침 없음. 실제 글자 경계+2px가 피스 내부에 포함되는지도 확인했다. 시각 검토에서 보내다가 홈 테두리에 가까워 21→18px로 보완했다.
- 기본 headless 실행은 브라우저 경로/공유 라이브러리 부재로 실패했다. 기존 Chromium 경로를 지정하고 필요한 라이브러리를 `/tmp`에만 풀어 실행했다. 본편 패키지·운영체제 패키지 설치는 하지 않았다.
- 비교 HTML의 Windows 기본 앱 열기 요청은 종료 코드 0으로 완료했다([열기 결과](열기결과.json)). 동일 HTML의 headless 렌더 화면은 직접 확인했으며, 실제 Windows 창 표시까지 확인했다고 주장하지 않는다.
- 남은 경험 증거: 사람의 초견 학습·접합 표식의 실제 부착 난도·자유 조립 손맛·재미. 에이전트 검토나 비교 버튼 동작을 그 증거로 바꾸지 않는다. 별도 사람 모집을 다음 설계의 선행조건으로 요구하지 않는다.

## 후속 검토 — 4안의 선택 난도와 제작 범위

- 현재 보내다 표본의 실제 모형 종류는 기존 **4종→8종**이다. 파랑은 무표지·위 입력 행위자·왼쪽 입력 행위자의 총 3종(2종 추가). 입력 노랑은 원형 E/S 2종과 두 갈래 E/S 2종. 출력 너의 W홈 1종은 유지된다. 피스 개수는 4개 그대로이며 **모형 종류 수와 한 문장의 피스 수를 혼동하지 않는다.**
- 단어마다 모형을 복제하는 구조는 아니다. 같은 모형에 나/주민 등 다른 글자를 넣는다. 하지만 접합 자리·방향·개수·표현 관계가 늘면 전체 외곽 종류는 증가한다. 생성기로 외곽 제작을 줄여도 목록 선택·규칙 학습·콘텐츠 판정 검사는 남는다. 이 작은 표본의 2배를 전체 제작량의 2배로 환산하지 않는다.
- 당장은 ‘행동하는 쪽’ 한 관계만 검토한다. 보내다에서 배운 관계가 밀다 같은 다른 행동에도 같은 뜻으로 읽히는지, 손+아프다 같은 상태에는 불필요한 역할 구별을 강요하지 않는지 비교하는 것이 다음 범위다. 다른 행동의 연결 개수가 다르면 같은 규칙을 쓰더라도 전체 외곽은 추가로 필요할 수 있다.
- 모형 찾기는 돌출/홈·방향 등 물리 호환을 쉽게 확인하게 할 수 있다. 상황에 맞는 정답 단어나 행위자를 대신 선택하는 필터를 추가하는 것은 아니다. 목록 UX를 이번에 구현하거나, 표현을 어렵게 만들려고 호환 안내를 금지하지 않는다.
- 목표를 같은 의미로 전달할 수 있다면 기존 모형의 글자 교환도 허용한다. ‘어렵게 모형을 바꿔야 재미있다’는 이유로 더 짧은 동등 표현을 차단하지 않는다. 모형 선택의 복잡함 자체를 소통의 깊이로 평가하지 않는다.
- 에이전트 `relation_alternatives06`는 ‘결과가 달라지는 모든 의미를 명시’는 너무 넓다고 반박했고, ‘게임이 선택하게 하는 의도를 구별’하는 기준으로 좁혔다. `jigsaw_geometry`는 위 4→8 모형 계산과 단어별 복제 불필요, 접합 배치에 따른 증가, 상태 서술에 무조건 확대할 수 없는 점을 검토했다. 이번 후속은 설계·범위 검토이며 새 플레이 실험을 수행한 것이 아니다.

이후 같은 상황의 상반된 두 의도와 다른 단어 재사용은 [재사용 07](../재사용07/검토와결과.md)에서 비교했다. 4안의 전면 도입, 전역 주어/목적어 문법, 새 본편 제작으로 확대하지 않는다.
