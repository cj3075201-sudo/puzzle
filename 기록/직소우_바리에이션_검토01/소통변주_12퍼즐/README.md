# 열두 가지 대화 — 직소우 소통 퍼즐

2026-09-29. 사용자 “각각 상황에 맞는 퍼즐 만들어서 보여줄래? 해봐야 알거같네” 승인으로 후보 12개를 플레이 표본으로 제작했다.

[플레이 열기](플레이.html). 파일 하나를 Edge/Chrome으로 열면 실행된다. 서버·인터넷 연결 불필요. 번호별 조립판, 대화, 완료 상태와 평가를 같은 브라우저에 저장한다.

## 조작

인물 클릭으로 말을 듣는다. 모형을 골라 빈 칸에 놓고 글자를 넣는다. 돌출부와 홈을 연결하고 상대를 선택한 뒤 ‘말해 보기’를 누른다. 끌기/클릭 이동, 삭제, 되돌리기, 단계별 힌트 제공. 모형 회전 없음. 노랑 대상·파랑 행동/상태, 대상→행동 방향을 유지한다.

## 비교할 퍼즐

|번호|상황|생각할 내용|
|---|---|---|
|1|두 사람의 나|화자의 ‘나’를 듣는 상대에게 맞춰 지칭|
|2|창 너머에서 아는 것|상대가 볼 수 있는 정보로 주민 특정|
|3|상자가 멈춘 자리|두 증언에서 같은 대상을 연결|
|4|뒤바뀐 부탁|전달자가 바꾼 주인·목적지 정정|
|5|한 사람의 두 불편|두 조건이 같은 사람에게 속하도록 연결|
|6|장치를 아는 사람|현재 상태와 원하는 상태를 구분해 전달|
|7|질문 조각은 어디에?|어느 부분을 모르는지 질문 범위 선택|
|8|무엇이 아닌가?|상태 부정과 행동 부정 구별|
|9|언제 아픈가?|통증이 생기는 조건 구별|
|10|그때 열린 문, 지금 열린 문|정보가 맞았던 시점과 현재 구별|
|11|누가 그렇게 말했나?|남의 말 전달과 현재 사실 전달 구별|
|12|먼저 설 사람, 잡아 줄 사람|상대의 조건을 읽고 역할·순서 조율|

1–6은 기존 연결 활용, 7–12의 질문·부정·조건·시점·인용은 이 묶음에서 시험하는 임시 문법이다. 개별 화면에 해당 읽기 규칙을 표시했다. 새 본편 Unity 구현 보류는 유지한다.

## 제작과 검증

- 기존 연결확장08의 실제 직소 외곽 재사용. 96개 모형 데이터 중 23개를 조립 메뉴로 제공. 글자와 모형 분리.
- 좌표나 형제 순서에 종속되지 않는 연결 트리 판정. 조립 가능성·모형 접합·노랑 연속 길이·범위 확인.
- core 19검사, 1–6 판정 344 assertions, 7–12 판정 31테스트 통과.
- Windows Edge에서 12개 모두 모형 선택→칸 배치→글자 입력→발화→완료를 UI 이벤트로 검증. 전체 128검사 통과: [결과](browser-results.json).
- 독립 검토로 8·9·12의 대상→행동 방향 수정. 2의 위치+소지물 동시 설명, 6의 정확한 손·발 동시 설명 수용. 6·12 목표의 풀이 노출 축소.
- Edge를 종료하고 다시 실행한 뒤 조립판·상대·대화·상황 복원 및 496px 화면 가로 넘침 없음 확인: [추가 4검사](reload-results.json).
- [실행 화면](플레이_검증.png). 사람의 체감 난도와 재미는 다음 사용자 플레이로 평가한다.
- 판정은 각 상황에 정의한 어휘와 의미 트리를 처리한다. 새로 발견되는 타당한 표현은 사례별로 추가한다.

## 소스

`app.js` 조작·저장, `scene.js` 상황 표현, `core.js` 접합/의미 분석, `scenarios-a.js` 1–6, `scenarios-b.js` 7–12, `style.css` 화면. `python3 만들기.py`로 단일 HTML을 생성한다. 글꼴 서브셋에는 fontTools가 필요하다.

검사: `node --test core.test.js scenarios-a.test.js scenarios-b.test.js`. 브라우저 시나리오는 `browser.test.js`이며 테스트 저장 키를 사용해 사용자 진행을 보호한다.
