# 핵심 표본24 UI 시험계획

2026-09-30 · 플레이 시작 전

## 참가자와 정보

- 정보차단 참가자는 신규 대화 이력·설계·해법·소스를 받지 않는다. 제공된 브라우저 클라이언트로 렌더링된 화면과 실제 좌표 입력만 사용한다.
- 메인은 QA/설계를 알며 그 플레이를 초견으로 기록하지 않는다. 제작자 교차 시험 역시 정보차단 참가자와 합쳐 평균을 내지 않는다.
- 제작자 상태 검사는 가능한 해법·동등 표현·재시도·세이브의 기능 증거다. 실 플레이 재미의 증거로 쓰지 않는다.

## 관찰

각 중요한 세계 행동이나 발화 전에 현재 가설과 예상 결과를 짧게 기록한다. 관찰 후 무엇이 달랐고 다음 선택이 왜 바뀌었는지 기록한다. 동일한 문장을 조립하는 낱개 클릭마다 불필요한 생각 메모를 강요하지 않는다.

이 기록은 시험 로그이며 게임 UI에 새 사고 과제/체크리스트로 추가하지 않는다. 빨리 풀기, 일부러 오래 기다리기, 특정 시간/해법을 맞추기 모두 요구하지 않는다.

## 구별할 막힘

- 추론: 가능한 해석·경로·조건을 비교하고 실험을 고르는 고민.
- 문법: 의도는 정했으나 모형·연결·표현 인식에 막힘.
- UI: 조립 조작·스크롤·월드 대상 찾기·읽기.
- 정보 부족: 화면에서 중요한 규칙이나 구별할 근거를 찾을 수 없음.

## 결과와 반복

첫 성공 경과는 최초 화면 관측부터 최초 성공 반응 관측까지의 실제 로그 차이. 사고·입력·도구 지연이 포함되므로 사람시간으로 환산하지 않는다. 클릭, 발화, 세계행동, 거절, 힌트와 주요가설 전환을 별도로 기록한다.

초기정보에서 읽어낸 단일답을 반복명령으로 실행하는 것과, 여러 제약을 비교해 완결계획을 머릿속에서 먼저 세우는 것을 구별한다. 전자는 핵심 깊이 부족의 증거다. 후자가 빠르거나 첫 시도에 성공했다고 나쁜 퍼즐로 판정하지 않는다. 새로운 기능이나 총 소요시간으로 얕은 선택 구조를 덮지 않는다. 관찰로 얻어야 하는 정보가 초기설명에 이미 정답 형태로 주어졌는지도 확인한다.

주요 결함이 있으면 먼저 구조/정보/판정을 고친다. 수정 전·후를 구분하고 한번 본 참가자의 재시험을 새 초견으로 세지 않는다. 합리적인 우회 성공은 보존하고, 특정 질문이나 문법을 썼다는 플래그로 성공을 잠그지 않는다.

## 기록 보관

원본 HTML/소스와 SHA-256, UI 행동 JSONL, 각 상태의 렌더링 텍스트/컨트롤/스크린샷, 참가자 가설 메모, 발견된 결함과 수정 내역, 최종 QA 결과를 보관한다. 결과 페이지는 스포일러 없는 플레이 입구와 접힌 풀이/분석을 구분한다.
