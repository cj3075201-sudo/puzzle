# 여러 퍼즐 변주 비교 · 사전 시험 계획

2026-09-30 사용자 요청: 여러 방안 발상 → 실질적 의미 검토 → 에이전트 플레이 → 기존 대비 시간·막힘·의미 분석. HTML 시험 제작까지 이번 요청의 구체 산출물로 진행한다. 본편 채택은 별도다.

## 비교할 여섯 축

| 표본 | 예상 차이 | 반증할 가능성 | 기존 비교 기준 |
|---|---|---|---|
| A1 지속 조건 지시 | 한 번의 동작 대신 여러 상태에서 작동할 부탁을 설계 | 정답 조건만 넣는 일회성 퀴즈 | 21 부탁판, 변주12 순서 |
| A2 고정 이름·변하는 역할 | 상태가 바뀔 때 유지할 대상과 다시 찾을 대상 구별 | 이름만 외우고 매번 직접 지시해도 동일 | 19 사라지는 단서, 22 동일대상 |
| A3 집단·예외 | 남길 역할을 고려해 행동 범위 선택 | 개별 지시 클릭을 줄이는 편의만 있음 | 16 자리바꾸기, 18 물건교환 |
| B1 원인을 가르는 실험 | 어떤 행동이 여러 가설을 구별할지 선택 | 실험 순서가 사실상 고정, 전부 눌러 해결 | 변주7 질문, 9 조건 |
| B2 상대의 오해 수정 | 내가 아는 사실과 상대가 믿는 사실 구분 | 증거 획득→제출의 고정 심부름 | 변주2 관점, 11 출처 |
| B3 상충 부탁의 목적 조정 | 겉 행동 요청 뒤의 목적을 함께 만족 | 대화 없이 도구만 써도 동일 | 20 누구의 손, 변주6 장치 |

이는 시험 전 가설이다. 제작자와 시험자의 실제 결과를 확인한 뒤 결론을 내린다.

## 참가자·순서

- C: 대화·설계·해답을 받지 않은 새 에이전트. 기준19→22 두 장면→기존 변주7·11 후 새 6표본을 익명 케이스로 플레이한다. 따라서 새 표본은 조작 학습 뒤 첫 접촉이며, 완전 무경험 게임 초심자를 뜻하지 않는다.
- A제작자: B묶음만 해답·소스 없이 화면 플레이. B제작자: A묶음만 동일 방식. 이 둘은 자신의 제작과 공통 엔진 구조를 아는 교차 검토자다. C와 동일한 완전 정보차단 표본으로 합산하지 않는다.
- 신규 각 장면 최소 C의 초견 1회 + 타 제작자 교차 1회를 목표로 한다. 결함 수정 뒤 같은 사람이 재시도한 것은 첫 시도 시간에 덮어쓰지 않는다.
- 복사 HTML을 참가자별 독립 브라우저 저장영역에서 실행한다. 원본 HTML 해시와 복사본 해시를 보관한다. 신작 시험 중 원본이 수정되면 버전을 구분해 재시험한다.

## 실제 입력과 시간

UI 전용 CDP 브로커로 화면 글자·스크린샷·클릭 좌표만 공개한다. 숨은 상태·소스·테스트 API·정답 주입을 금지한다. 한 번의 조립에는 여러 클릭이 포함된다. 화면에 표시된 일반 문법 설명은 읽어도 되며 장면별 힌트와 대표 풀이 사용은 별도 기록한다.

장면 진입 관측에서 최초 성공 반응 관측까지의 실제 경과, 첫 제출까지 경과, 클릭·제출·실패·힌트 수, 가장 긴 관측 간격을 로그로 산출한다. AI 추론·도구 처리·출력 읽기가 포함된다. 순수 사고 시간을 로그로 분리할 수 없으므로 만들지 않는다. 사람이 걸릴 시간으로 환산하거나 시간 증가 자체를 재미·깊이로 평가하지 않는다.

막힘은 관측과 참가자 설명으로 조립/UI, 문법, 단서 해석·논리, 구현 결함으로 분류한다. 근거가 약하면 혼합/미확인으로 남긴다. 6분 동안 진전이 없으면 게임 힌트, 10분 이상 완료 못 하면 미완료로 기록하고 다음 장면으로 간다.

## 의미 판정

1. 실제 입력 전에 어떤 정보로 무엇을 선택했는가.
2. 상태가 바뀐 뒤 같은 답을 반복할 수 있었는가, 판단 이유가 바뀌었는가.
3. 새 기능을 빼거나 개별 지시로 풀면 무엇이 달라지는가.
4. 오답이 다음 판단에 필요한 정보를 주었는가.
5. 같은 원리를 다른 사건으로 옮겼을 때도 새로운 판단을 만들 여지가 있는가.
6. 기능은 작동했으나 판단 증가 근거가 없다면 편의/도입용/재설계로 결론낸다.
