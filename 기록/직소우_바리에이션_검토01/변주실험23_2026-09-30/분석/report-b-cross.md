# B 제작자의 A 묶음 UI 교차 플레이

시험 범위: A의 소스·설계·정답·API를 읽지 않고 브로커가 돌려주는 화면 텍스트·접근 가능한 컨트롤의 표시 이름/좌표·스크린샷만 사용했다. B 제작을 하면서 공통 직소 엔진과 모형 접합을 이미 아는 참가자이며, 정보차단 초심자 C와 분리한다. 화면 글자와 모형을 정확히 좌표 클릭하는 작은 헬퍼를 사용했다. 내부 트리 주입·정답 조회·자동 솔버는 사용하지 않았다. 헬퍼는 내가 정한 모형/칸/글자를 화면 표시 이름으로 찾아 클릭했다.

시간은 actions.jsonl의 participant b의 첫/마지막 UI 로그 시각 차이다. UI 도구 처리, 응답 읽기, 판단과 헬퍼 작성 시간이 포함된다. 사람 플레이타임으로 환산할 수 없다.

## case06: 규칙의 진리 조건을 시험하는 차이는 분명함

처음 표를 보고 첫/둘 운반 모두 물이 낮고 홍수만 높다는 것을 확인했다. 책은 둘째 운반에는 없고 홍수 때 있으므로 기존 약속의 조건으로 부적절하다. 종을 쓸 수도 있지만 나는 원인에 더 직접적인 `문→닫다→때→물→높다`를 만들었다(27). 운반자에게 `운반→시작하다`를 말하자 두 수레 통과와 홍수 차단을 모두 확인했다(40).

새 의미는 현재 한 번 맞는 말을 고르는 것이 아니라 여러 상태에서도 같은 약속이 맞는지 비교하는 것이다. 조건 선택이 실제로 바뀌는 근거가 표에 있다. 단순 기존 명령 전달보다 강한 변주다. 현재 3행 표가 모든 조건을 한눈에 주므로 나에게 논리 막힘은 없었다. 더 어려운 게 아니라 지속 규칙을 실용적으로 익히는 대표 표본으로 평가한다. 기존 약속으로 실패를 실제 실행하지는 않았고, 실패 가능성은 화면 표로 판단했다.

증거: 06/001 초기 조건표, 06/027 물 조건 약속 채택, 06/040 세 상황 통과표.

## case04: 같은 사람과 바뀌는 역할의 구별은 좋지만 새 문법 없이도 해결됨

수리/모루/도루/관리인의 말을 순서대로 들었다(2~5). 환자의 통증이 사라져도 치료 안정은 남으므로 `계속→수리→쉬다`로 이름을 고정했다(19). 반면 열쇠는 교대하면서 소유자가 바뀌므로 `계속→주민(가지다→열쇠, 열다→문)`으로 당번을 상태로 선택했다(45). 운반을 두 번 말해(55,56) 오전과 오후를 완료했다.

판단 차이는 이름=개체 고정, 상태=그때의 역할 재선정이다. 지속 규칙과 잘 결합한다. 두 교대만으로는 반복 절감 효과가 작지만 세 번 이상 교대/대상 변동이 있는 장면에 유효할 수 있다. 현재 설명이 그 구별을 꽤 직접 알려주므로 어려운 지칭 추리로 볼 수는 없다.

후속 대안: 모든 첫플레이가 끝난 뒤 UI 이전 버튼으로 장면2에 돌아가 다시 시작했다. 증거 파일 이름은 브로커의 마지막 case08에 계속 저장된다. `수리→쉬다`, `모루→열다→문`, `운반→시작하다` 후 오후에 `수리→쉬다`, `도루→열다→문`, `운반→시작하다`로 완료했다. 계속 없이도 성공한다. 08/049~120 별도 구간, 20.284초, 발화6회. 첫 플레이 발화4회보다 2회 늘었다. 모든 문장을 다시 지우고 만든 현재 대안 조작은 72기록(시작 포함)이고 첫 경로는 56기록이었다. 학습 후 대안이므로 벽시계 시간이 더 짧은 것을 편의 개선의 반증으로 쓰면 안 된다. 표현 선택과 반복 비용이라는 효용을 함께 본다.

증거: 04/019 이름 고정, 04/045 역할 선택, 04/055 교대 변화, 04/056 완료. 대안 08/062·076·086·096·110·120.

## case08: 집단/제외는 현재 세 명 규모에서 입력 비용을 줄이지 못함

초기 상태에서 모루가 발판을 지키며 나머지 둘이 대기하는 것을 봤다. 화면의 일반 문법에 따라 `모두→주민(제외→모루, 밀다→상자)`를 조립해 한 번 말했고 완료했다(28). 모형/글자 색은 스크린샷으로 확인했다. 처음 생성한 헬퍼가 텍스트 없는 컨트롤을 처리하지 못해 Python KeyError가 한 번 났지만 UI 입력·퍼즐 판정 이전의 도구 오류였다. 게임 실패 횟수에 넣지 않았다.

후속 대안은 같은 화면의 다시 시작을 사용했다(30). `수리→밀다→상자`를 한 번 보내고(45), 맨 앞 글자만 도루로 바꿔 다시 보냈다(48). 08/029~048, 3.884초. 집단은 6피스·한 발화, 개별은 3피스·두 발화지만 두 번째는 글자 하나만 바꾸면 된다. 선택한 UI 절차에서 집단 조립+전송 25클릭, 개별 조립+전송+이름교체+전송 16클릭이었다(색 필터 선택 포함). 집단이 실제 조작을 더 줄인다는 주장은 이 표본에서 성립하지 않는다.

남겨야 할 사람을 판단한다는 의미는 있으나 개별 이름 지시에서도 정확히 같은 판단이다. 새 집단 문법의 고유 효용은 짧은 한 문장으로 범위를 압축한다는 점이며, 대상 수가 둘인 지금은 조립 비용에서 불리하다. 셋 중 확대 우선순위는 낮다. 기능 강제 불합격 없이 개별 해법을 인정한 것은 타당하다.

증거: 08/001 초기 역할, 08/028 집단1회 완료, 08/045 개별1명 진행, 08/048 개별2회 완료.

## 비교 판단과 막힘

추천: 06 지속 조건 > 04 이름/역할 재선정 > 08 집단/제외. 셋 모두 현재 장면은 일반문법과 상태표만으로 쉽게 풀린다. 06과 04는 미래 상태가 변할 때 어떤 표현이 계속 유효한지 다르게 생각하게 한다. 08은 같은 사람 선별을 복잡한 표현으로 압축한 편이며 현재 대상 수에서는 뚜렷한 비용 이득이 없다.

논리 막힘과 접합 실패는 없었다. 나는 기본 외곽과 모형 메뉴를 알고 있어 곧바로 한 줄/분기형 조립을 설계했다. 처음 보는 사람의 피스 선택·방향 파악 병목은 이 결과로 평가할 수 없다. 화면 상단의 NPC와 하단 발화 버튼을 오가며 스크롤한 것은 있었으나 플레이를 중단시킬 문제는 아니었다. 반면 충분한 설명으로 모든 답을 바로 알 수 있었으므로 이 표본을 고난도 퍼즐의 증거로 확대하면 안 된다.
