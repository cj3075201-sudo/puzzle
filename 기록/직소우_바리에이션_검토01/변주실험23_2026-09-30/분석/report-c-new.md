# C 신규 6장면 UI 시험

기준5장면을 통해 UI와 일부 문법을 익힌 AI 참가자의 신규 설계 첫접촉. 설계·해답·소스·숨은 JS·다른 참가자 기록 안 읽음. 렌더 화면과 UI client만 사용. 전부 첫판, 힌트0, 성공 후 추가 시험 없음. 실제 경과는 도구/관측 포함이며 인간 체감시간 또는 순수 사고시간 아님.

무힌트 6/6 완료. 처음 보는 구조적 판단은 04 고정 이름/변동 상태 참조, 06 조건 선택, 05 관측으로 진단에 있었다. 09 시야에 따른 믿음 변화와 07 서로 다른 목적 합의는 스토리 의미가 분명했으나 화면 안내가 해결을 상당히 공개한다. 08은 개별 명령으로 새 문법 없이 통과해 목표 성공과 문법 습득을 분리해야 한다.

## 06 / 홍수 때 닫히는 문

시작 2026-09-29T18:20:16.718424+00:00 step1 → 첫 제출 2026-09-29T18:20:39.000353+00:00 step24 → 완료 2026-09-29T18:20:47.597797+00:00 step35. 경과 30.9초. 거절 0회, 힌트0.

두 수레 때 물이 낮고 홍수 때만 높으므로 문→닫다→때→물→높다를 지속 약속으로 선택했다. 종이 울릴 때 열기도 성립할 것으로 보였지만 홍수 방지 목적을 직접 표현하는 닫기 조건이 더 자연스러웠다. 운반자에게 운반→시작하다로 시험.

첫판부터 조건의 참/거짓에 따라 반대 행동이 생기는 규칙을 읽고 세 행을 비교했다. 기존 책 조건이 둘째 운반/홍수에서 왜 틀리는지도 분명했다. 다른 조건을 선택해도 받아들여졌고 결과표가 인과 확인을 돕는다. 다만 작은 진리표가 이미 모든 상황을 공개해 판단은 짧았다.


조작: 세로 길이로 스크롤 1회 필요. 도구/관측 포함 경과이며 사고시간 아님.

다른 의도 유효성: 종 조건 대신 물 높음→닫기를 사용해 실제 성공. 대안 추측이 아니라 첫판 관측.

## 05 / 울리지 않는 이유

시작 2026-09-29T18:20:51.322887+00:00 step1 → 첫 제출 2026-09-29T18:21:08.262288+00:00 step11 → 완료 2026-09-29T18:21:21.881145+00:00 step22. 경과 30.6초. 거절 1회, 힌트0.

전원이 둘에 연결된 원인이므로 처음엔 전원 시험을 계획했다. 이후 종이 안 울리고 램프가 켜지는 관측으로 전원은 살아 있고 종 자체가 고장이라고 좁혔다. 종→고치다 1회로 성공.

관측이 새 정보를 주어 가설이 바뀌는 구조는 좋았다. 그러나 독립 부품 둘+공통 전원/하나만 고장으로 고전적 간단 진단. 2회 관측 후 1회 수리; 잘못된 수리는 없음.

- 전원 직접시험 불가를 알려 주는 장치 클릭과 미리 계획한 전원 조립을 같은 호출 묶음에 넣었다. 새 문장을 받은 뒤 적응하기 전에 전원 시험까지 진행되어 거절1회. 이 1회는 숙고 후의 오해보다 사전계획 UI 배치 제약이 섞인 관측이다.

조작: 거절 step11은 형상/문법 오류가 아니라 허용되지 않은 시험 대상.

다른 의도 유효성: 받침 시험이나 무관 부품 교체는 하지 않았다.

## 04 / 바뀌는 당번, 같은 환자

시작 2026-09-29T18:21:26.184031+00:00 step1 → 첫 제출 2026-09-29T18:21:38.130395+00:00 step16 → 완료 2026-09-29T18:22:02.196907+00:00 step53. 경과 36.0초. 거절 0회, 힌트0.

하루 쉬어야 하는 대상은 상태가 아니라 고정 이름 수리로 지정했다. 문 여는 사람은 열쇠가 이동하므로 주민에서 가지다→열쇠와 열다→문을 갈라 지정했다. 각각 계속을 붙이고 오전과 오후 운반을 실행.

같은 환자와 바뀌는 당번을 다른 참조 방식으로 고르게 만드는 차이가 실제 상태 전환으로 드러났다. 이 여섯 개 중 언어 지칭 차이를 가장 분명하게 활용했다. 단서가 처음부터 차이를 명시해 틀릴 이유는 적었고 조각 입력이 주된 실행비용이었다.


조작: 6조각 가지를 만들기 위해 모형/색 교체와 칸 선택 다수. 형상 실패는 없었음.

다른 의도 유효성: 오후에 이름 부탁을 갈아 끼우는 대안은 시험 안 함. 지속 참조 두 종류를 첫판에서 사용.

## 09 / 안전해도 건너지 않는 사람

벽 뒤에서는 변화가 안 보인다는 말에 여행자를 먼저 관찰창으로 이동시켰다. 기사에게 수문을 열게 하여 물이 옆 수로로 흐르는 것을 보여 주고 여행자에게 건너기를 부탁했다.

바깥 사실과 인물의 믿음이 별도로 변한다는 점이 화면에 드러난다. 직접 보여 주는 순서가 이야기와 맞아 설득력 있다. 다만 안전한 관찰창/볼 수 있는 변화라는 안내가 해결 순서를 거의 말해 주었다.


조작: 여행자 이동 후 새 위치를 스크린샷으로 확인하여 클릭.

## 08 / 한 사람은 남아야 한다

시작 2026-09-29T18:22:47.694855+00:00 step1 → 첫 제출 2026-09-29T18:22:59.209534+00:00 step15 → 완료 2026-09-29T18:23:03.008583+00:00 step18. 경과 15.3초. 거절 0회, 힌트0.

감독이 개별 부탁도 유지된다고 하므로 수리→밀다→상자를 먼저 부탁했다. 1명이 합류를 기다리는 반응을 확인한 다음 주어만 도루로 바꿔 두 번째 부탁. 모루의 발판 일을 유지해 성공.

목표 해결은 명확하고 유효한 대안이 실제 허용되었다. 다만 모두/제외라는 새 문법은 필요하지 않았다. 조립3개+주어변경이 복잡한 제외 가지보다 덜 수고스러워 이 경로를 자발적으로 선택했다. 첫판 성공만으로 새 문법을 익혔다고 평가하면 안 된다.


조작: 중간 “1명뿐이라 기다린다”는 실패가 아니라 계획한 진행 상태.

## 07 / 열어 달라, 닫아 달라

시작 2026-09-29T18:23:07.717147+00:00 step1 → 첫 제출 2026-09-29T18:23:21.342680+00:00 step15 → 완료 2026-09-29T18:23:42.927846+00:00 step35. 경과 35.2초. 거절 0회, 힌트0.

질문→정원사→원하다와 질문→돌보미→원하다로 물 공급/물고기 유지라는 목적을 분리했다. 장치 설명에서 격자는 물만 통과하고 천은 둘 다 막는다고 확인. 닫힌 문에 격자를 끼운 뒤 수문을 열었다.

서로 반대처럼 보이는 지시의 이유를 물어 공동 목표를 찾는 흐름은 내용이 좋다. 하지만 장치가 각 재료 결과를 명시해 조작 전에 해법이 거의 확정되었다. 실제 결과 확인은 있지만 시험-가설수정 없이 정보수집 후 곧바로 끝났다.


조작: 문법은 기존 질문 패턴을 알고 있어 새로운 비용이 거의 없었음.

다른 의도 유효성: 천/열림 상태 교체/물고기 이동 복구는 시험 안 함.
