## 결론과 범위

**이번 능동행동 표본에서는 같은 행위자 관계 규칙을 재사용할 수 있고, 대화별 목록을 제한해도 두 사람의 반대 역할과 무표지 표현을 유지할 수 있다.** 다만 관계 규칙이 같다는 것과 낱개 외곽·전체 조립이 같다는 것은 구별해야 한다.

후속 질문의 핵심은 **관계 표시형만 남겼다고 가정해도 문맥을 활용해야 하는 문장이 가능한가**였다. AI가 ‘무표지도 유지한다’고만 답한 것은 질문을 충분히 다루지 못한 설명이며, 사용자가 이를 정정했다. 표시형만 쓰는 가정과 두 형태의 병용 효용을 아래에서 분리해 검토했다. 이 질문을 무표지 폐기나 모든 대화의 표시형 강제에 대한 결정으로 기록하지 않는다. 현재 비교 화면에는 두 형태가 있으며 관계 표시 상태를 먼저 보여주고 ‘기본 연결’로 전환할 수 있다. 사용자의 ‘너를’과 이번 시험에서 한정한 ‘너에게’는 목적어/도착 상대가 다른 예시다. 시험의 도착 상대 가정이 사용자의 원래 문형을 대체하는 확정 문법은 아니다.

| 발화 | 제시 항목 | 실제 발화 피스 | 확인한 재사용과 차이 |
|---|---:|---:|---|
| 보내다 | 6종 | 4개 | N/W 두 입력+도착 상대 출력. N 두 갈래가 보내는 쪽. 원형 모형도 제공 |
| 밀다 | 5종 | 3개 | 행위자 규칙 재사용. W 두 갈래로 방향을 바꾸고, 도착 상대 출력은 없는 다른 파랑 외곽 사용 |
| 당기다 | 5종 | 3개 | 밀다의 모형 목록 5종과 완성 외곽 전체를 재사용. 행동 글자가 달라짐 |
| 아프다 | 2종 | 2개 | 상태 대상 한 곳을 기본 연결로 표현. 손/발을 바꿀 수 있고 행위자 선택을 요구하지 않음 |

- ‘보내다’의 파랑에 ‘밀다’를 그대로 넣었다고 같은 역할 구조가 완성되는 것으로 설명하지 않는다. 이번에는 입력/출력 수가 다르다.
- 보내다→밀다는 행위자 의미와 노랑 원형 2종을 공유한다. 표시 방향을 바꾼 것은 ‘위쪽이 항상 행위자’라는 해석과 구별하기 위해서다. 밀다/당기다는 같은 참여자 수·형태에서 완전 재사용된다.
- 기본 비교에 쓰인 전체 집합은 색+외곽으로 구별한 메뉴 항목 **10종**이다. 순수 외곽만 비교하면 파랑 아프다의 W홈과 노랑 출력 대상의 W홈이 같아 **9종**이다. 이 수량 차이를 새로운 문법 차이로 취급하지 않는다. 대화별 6/5/5/2는 이번 구성의 필요량이며 전역 제한 수치를 확정한 것이 아니다.
- 상태 표현에는 ‘행동하는 쪽’을 강제로 붙이지 않는다. 원형 연결은 ‘피동자’라는 전역 뜻을 갖지 않는다. 이번 발화 문형을 능동행동/상태로 구분했으며, 향후 다의어의 모든 용례를 한 종류로 고정한 것은 아니다.

## 모형 목록을 줄이는 기준

1. 표시할 모형은 해당 대화에서 표현할 내용과 배운 모형을 기준으로 고른다. **숨은 정답에 맞춰 선택지를 바꾸지 않는다.** 나→주민과 주민→나 중 어느 것을 말할지 달라도 메뉴·순서·각 모형에 넣을 수 있는 글자는 같다.
2. 같은 뜻의 모든 외곽 변형을 매번 보여줄 필요는 없다. 보내다는 표시가 위쪽인 형식, 밀다/당기다는 표시가 왼쪽인 형식만 제시해도 글자 교환으로 양쪽 행위자를 말할 수 있다. 표시하지 않은 원형 발화도 제시 집합 안에 남긴다.
3. 목록은 문장 형태를 유도하는 힌트가 될 수 있다. 이번 검토에서 확인한 것은 **그 목록만으로 정답 인물까지 정해지지는 않는다**는 점이다. 어떤 단서도 주지 않는 목록이라고 과장하지 않는다.
4. 발견한 모형이 목록 밖에 있다고 습득 기록을 지우거나 소모하지 않는다. 대화별 제시 제한과 누적 재사용을 구별한다. 사용자 제안을 우회하는 전체 목록 버튼을 자동 추가하지 않는다.
5. 실제 선택지로 허용한 의도를 표현할 재료가 빠져 있으면 대화 제작의 문제로 처리한다. 더 짧거나 다른 글자 배치로 같은 뜻을 표현할 수 있는데 외곽 복사만 정답으로 강제하지 않는다.

보내다의 6종은 파랑 무표지/위 표시 2종, 노랑 E원형·S원형·S두갈래·W홈 4종이다. 밀다/당기다의 5종은 파랑 무표지/왼쪽 표시 2종, 노랑 E원형·E두갈래·S원형 3종이다. 아프다는 파랑 W홈과 노랑 E돌출만 필요하다. 모형의 수량을 한 장씩 소모하는 재료 제한으로 바꾸지 않는다.

## 관계 표시형만 쓸 때의 문맥 — 후속 설계 검토

**논리적으로 가능하다.** 관계가 명시되어도 말이 가리키는 실제 대상, 한 글자에 허용된 의미 범위, 표시하지 않은 발화 의도까지 자동 확정되지는 않는다. 다만 표시한 행위자와 대상을 문맥으로 뒤집을 수는 없으므로, 원래의 ‘누가 보내는가’ 추론을 그대로 보존하는 안은 아니다. 맥락 추론의 대상이 바뀐다.

| 설명용 사례 | 표시로 고정되는 것 | 문맥으로 읽을 것과 실제 선택 | 적용 경계 |
|---|---|---|---|
| 시험의 보내다: A가 주민을 B에게 보냄 | 보내는 쪽 A, 보내지는 주민, 도착 상대 B | 직전 대화가 특정한 주민이 누구인지에 따라 부를 사람·찾아갈 곳이 달라짐 | 기존 역할 구조와 모순 없음. 두 주민에게 단서가 똑같이 맞으면 하나만 정답 처리하지 않음 |
| 같은 보내다의 ‘나/너’ | 행위자/보내지는 사람/도착 상대의 자리 | 실제 화자·청자를 관찰해야 나/너가 누구인지 알 수 있음 | 기존 어휘로 성립하지만 말풍선 대상 확인만으로 끝나면 퍼즐 깊이는 작음 |
| 후보 어휘: 너가 끈을 풀다 | 행위자 너, 대상 끈 | 묶음을 해제할 때는 고정 매듭, 길이를 내줄 때는 감긴 줄을 풀어내는 조작을 선택 | ‘풀다’가 두 용법을 포괄하는 글자로 설계·학습된다는 가정. 확정 어휘나 구현 아님. 화면에서 선택할 매듭/감긴 부분과 앞선 목적이 보여야 함 |
| 대안 후보 어휘: 너가 불을 끄다 | 행위자 너, 대상 불 | 화염 진압과 조명 소등을 구별해 대상·행동 선택 | 불/끄다의 허용 의미가 두 용례를 포괄할 때만 성립. 둘이 함께 있으면 추가 지칭 단서 필요 |
| 보고와 요청 | 같은 행위자·대상·행동 | 끝난 일을 알려주는지, 지금 할 일을 요청하는지에 따라 다음 행동이 달라짐 | 별도 시제·발화 의도 표지를 두지 않는 경우의 후보. 현재 전역 문법 확정 아님 |

- 장면만으로 요구 행동 전체가 드러나 언어를 읽을 필요가 없다면 언어 추론의 근거로 세지 않는다. 상황은 대상/용법을 좁히고 발화는 필요한 행동을 전달하는지 함께 확인한다.
- 모든 단어가 한 뜻이고 명사의 실제 대상도 하나이며 필요한 행동 조건까지 표시한다면 남는 것은 문장 읽기와 실행이다. 이 경우에도 깊은 문맥 추론이 남는다고 주장하지 않는다.
- 다의어는 반복 가능한 공통 의미 범위와 관찰 근거로 설계한다. 문제마다 ‘보내다=죽이다’처럼 임의의 숨은 뜻을 추가하는 방안은 제외한다.
- 서로 다른 의도를 플레이어가 말할 수 있게 설계했는데 같은 표시 문장만 받는다면, 실제 대상 선택·추가 단어 등 의도를 구별하는 관측 가능한 입력이 필요하다. 게임이 숨은 정답에 맞춰 플레이어 의도를 선택하지 않는다. 단서가 부족한 입력을 무조건 실패시키거나 의미 확인 근거로 세지 않는다.

**병용의 실제 용도:** 상대와 이미 공유한 역할을 생략하는 발화와, 역할을 특정하거나 다른 역할을 제안하는 발화를 함께 쓸 수 있다. 예를 들어 ‘나·너·밀다’라는 무표지 협력 제안을 상황으로 읽고, 플레이어가 표시형으로 누가 누구를 밀지 특정하거나 바꾸어 답하는 장면은 후보다. 매번 기본형을 표시형으로 옮겨 적게 하는 절차로 만들지 않는다. 같은 뜻을 유효하게 전달한 입력은 형태가 다르다는 이유로 거부하지 않는다.

현재 비교에서는 두 형태의 발화 피스 수가 같다. 따라서 무표지를 더 짧거나 더 빠른 조작이라고 설명할 근거가 없으며, 플레이어가 늘 표시형을 쓰는 선택도 합리적일 수 있다. 무표지의 유지는 역할 생략을 읽는 경험·발화 습관에 실제 용도가 있는지로 판단해야 한다. 모든 대화의 선택 목록에 두 형태를 항상 함께 넣을 의무로 확대하지 않는다.

**AI 추천:** 맥락을 보존하려면 무표지가 필수라는 전제를 철회한다. 표시형만으로도 대상·행동 의미를 해석하는 장면을 설계할 수 있다. 무표지 병용은 ‘역할 자체를 문맥에서 알아내는 경험’을 남길 가치와 모형/콘텐츠 부담을 별도로 비교한다. 현재 승인된 제한적 병용 시험을 자동 폐기하거나 표시형 전용을 새 확정 규칙으로 승격하지 않는다.

독립 검토: `relation_alternatives06`는 기존 보내다의 지칭·화자/청자 사례와 동일 조립 부담에서 무표지가 선택되지 않을 위험을 지적했다. 이력 없이 시작한 `marked_context_audit`는 역할/지칭을 구별하고, 불/끄다의 의미 범위를 사전에 정의한 사례를 제시했으며 원래 역할 추론 보존과 다른 문맥 추론의 성립을 구분했다. 끈/풀다 사례는 메인의 후속 설계 후보다. 이번 결과는 문장·조건에 대한 설계 논증이며 새 시각 자료·플레이·학습·재미 검증을 수행한 것이 아니다.

## 모형·화면 검산

- 메인 생성기는 [접합과 목록 검사](접합과목록_검산.json)에서 7개 렌더 배치의 홈/돌출 대응, 회전 없음, 메뉴 내 모형 사용, 양의 면적 겹침 없음을 확인했다. 밀다·당기다의 외곽이 같으므로 서로 다른 물리 형태는 5종이다.
- `jigsaw_geometry`는 별도로 14배치(능동행동 3개×무표지/명시×단어교환 2, 상태 대상 2)를 다각형으로 검산했다. 같은 의도의 다른 입력과 목록 수량을 검토했으며, 새 HTML이나 사람 플레이를 검사한 것은 아니라고 구별했다.
- 같은 밀다의 N표시 변형도 별도 기하 검산했다. 필요한 노랑 S두갈래는 보내다에서 재사용되며 파랑 1종이 추가된다. **이 검산용 변형은 이번 화면의 기본 10항목 목록에는 포함하지 않았다.** 모든 방향 변형을 동시에 보여줘야 한다는 뜻이 아니다. 같은 동사에서 다른 방향으로 표현하는 학습은 후속 콘텐츠 과제다.
- [브라우저 동작 검사](화면동작_검산.json): 네 단어의 표시, 대상 교환, 기본 연결 복귀, 파랑 모형 선택, 목록과 순서 불변, 밀다/당기다 목록 일치, 상태 문형에 행위자 표시 강제 입력 거부를 확인했다. 실제 글자 경계+2px가 피스 내부에 들어가는지 확인했고 브라우저 오류와 820px 가로 넘침은 없었다.
- 비교 PNG를 직접 열어 읽기 영역과 목록 배치를 확인했다. 상대 반응 애니메이션·월드 장면·자유 드래그는 이번 작업에 포함하지 않았다. 기능 확인과 사람의 학습·재미를 구별한다.
- 비교 HTML의 Windows 기본 앱 [열기 요청 결과](열기결과.json)를 기록했다. 실제 Windows 창 표시 여부와 별개로, 동일 HTML의 headless 렌더 이미지를 직접 확인했다.

이번 작업은 승인된 설계 비교를 완료한 것이다. 형상 규칙을 모든 조사·행동·상태에 확대하거나 기존 Unity를 수정하지 않았다. 다음 본편 설계에는 이처럼 **한 번 배운 관계를 다른 말에서 쓰되, 해당 대화의 표현 범위를 보존하는 작은 모형 집합**을 우선 적용한다.
